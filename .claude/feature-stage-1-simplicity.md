## 1. Зачем

Главная цель проекта — сделать сортировку и группировку файлов максимально простой. Сейчас до результата далеко:

- Чтобы разобрать папку, нужно знать 11 флагов и подобрать пару критериев `-c`/`-t`.
- Одна цепочка критериев действует на все файлы: нельзя разложить фото по годам, а документы по типам.
- `fiona tui` ничего не делает: результат выбрасывается (`cmd/fiona/main.go:53`). Предпросмотра плана в нём нет.
- Категория определяется по таблице из ~35 расширений, поэтому `.go`, `.md`, `.heic`, `.csv`, `.dmg` попадают в `unknown`.
- `date` даёт `January 2025`, `month` — `January`; README обещает `2025-01-15` и `01`.
- Откат требует помнить, где лежит журнал.
- План печатает каждый файл: на 350 файлов — 378 строк, и вопрос о подтверждении уезжает далеко от сводки.
- Треть вывода — баннеры, абсолютные пути и нулевые счётчики (`Renamed: 0`, `Replaced: 0`, …), итог запуска — 8 строк счётчиков.
- Вопрос `Would you like to continue?` не говорит, что именно произойдёт.
- «Нечего откатывать» — ошибка с кодом 1 и префиксом `Something went wrong`.
- В TUI логотип занимает 16 из 40 строк, деревьям остаётся по 7; source и dest стартуют в `~`, а не в текущей папке, и не связаны между собой.

### Целевой сценарий

```
$ fiona ~/Downloads
Sorting ~/Downloads with preset "downloads"

  images/       86 files   412 MB
  documents/    61 files    95 MB   exists
  archives/     12 files   1.2 GB
  installers/    9 files   2.1 GB
  code/          8 files   140 KB
  other/        38 files    52 MB   .torrent 20, .ics 9, .bin 4, …

  Left as is: 3 folders

Move 214 files (1.8 GB) into 6 folders? [y/N/l] y
✓ Moved 214 files in 1.2s. Undo: fiona undo

$ fiona undo
Undo the run from today 15:28 (moved 214 files in ~/Downloads)? [y/N] y
✓ Restored 214 files, removed 6 empty folders.
```

Ноль флагов, одно подтверждение, откат одной командой. Сводка помещается на экран, вопрос называет действие и объём, итог — одна строка.

## 2. Цели

- **Ц1.** `fiona <папка>` даёт разумный результат без единого флага.
- **Ц2.** Разным видам файлов — разные правила, в одном запуске.
- **Ц3.** Готовые пресеты и пользовательские — в одном конфиг-файле.
- **Ц4.** TUI проходит весь путь: папка → предпросмотр → выполнение → откат.
- **Ц5.** Большинство файлов попадает в осмысленную категорию; фото — по дате съёмки.
- **Ц6.** `fiona undo` без аргументов откатывает последний запуск.
- **Ц7.** Вывод читается с одного взгляда: сводка плана помещается на экран, вопрос называет действие и объём, итог — одна строка, ошибка подсказывает исправление.

### Вне рамок

- LLM в любом виде. Формат правил из раздела 3.2 проектируется как целевой для неё: модель будет выдавать тот же JSON.
- Web UI, watch-режим, дедупликация, облака, плагины.
- Перемещение папок как единого целого.
- Дата съёмки для видео.
- Сохранение пресета из TUI.
- Исправления ML-классификатора.

## 3. Решения

### 3.1 Командная строка

```
fiona [SOURCE]                       — то же, что fiona sort SOURCE
fiona sort [flags] [SOURCE] [DEST]
fiona undo [RUN-ID]
fiona history
fiona presets [show NAME]
fiona tui [SOURCE]
```

- **Позиционные аргументы.** `SOURCE` по умолчанию — текущая папка, `DEST` — равен `SOURCE`. Флаги `-s` и `-d` остаются синонимами.
- **Голая папка.** Если первый аргумент не подкоманда, а существующая папка, выполняется `sort`.
- **Без аргументов.** В интерактивном терминале запускается TUI, иначе печатается краткая справка.
- **Действие по умолчанию — `move`.** Сейчас это `copy`, что при dest == source удваивает файлы. После Этапа 0 перемещение безопасно и откатывается. Добавляется короткий флаг `--copy`.
- **Библиотека флагов — `spf13/pflag`.** Стандартный `flag` прекращает разбор на первом позиционном аргументе, поэтому `fiona sort ~/Downloads -r` не сработал бы. `pflag` снимает это ограничение и убирает дублирование коротких и длинных имён в `addFlag`. Цена: длинные флаги только с двумя дефисами.

Новые флаги `sort`:

| Флаг | Назначение |
|---|---|
| `-p`, `--preset <name>` | выбрать пресет |
| `--to <template>` | шаблон пути для всех файлов |
| `--copy` | то же, что `-a copy` |
| `-l`, `--list` | перечислить в плане каждый файл (3.8) |

Приоритет источников правил: `--to` → `-c`/`-t` → `--preset` → `default_preset` из конфига → встроенный `downloads`.

### 3.2 Шаблоны и правила

Пара «первичный + вторичный критерий» обобщается до шаблона пути. Правило — это условие и шаблон; побеждает первое подходящее.

```go
type Rule struct {
    Match Match  `json:"match,omitempty"`
    To    string `json:"to"`
}

type Match struct {
    Category []string `json:"category,omitempty"`
    Ext      []string `json:"ext,omitempty"`  // без точки, регистр не важен
    Name     string   `json:"name,omitempty"` // glob по имени файла
}
```

Плейсхолдеры:

| Плейсхолдер | Значение | Заменяет критерий |
|---|---|---|
| `{category}` | `images`, `documents`, … | `mimetype` |
| `{ext}` | расширение в нижнем регистре, `_no_ext` если нет | `extension` |
| `{year}` | `2025` | `year` |
| `{month}` | `01` | `month` |
| `{day}` | `15` | — |
| `{date}` | `2025-01-15` | `date` |
| `{size}` | `tiny` … `massive` | `size` |
| `{ml}` | тег классификатора | `ml` |

Семантика:

- В шаблоне допустим обычный текст; `/` разделяет компоненты.
- Каждый компонент после подстановки проходит санитайзер Этапа 0.
- Пустое условие подходит любому файлу.
- Файл, которому не подошло ни одно правило, остаётся на месте. План показывает: «Не затронуто: N».
- Неизвестный плейсхолдер — ошибка при загрузке с именем пресета и номером правила.
- `-c X -t Y` превращается в одно правило `{"to": "{X}/{Y}"}`.
- Классификатор запускается, только если `{ml}` есть в правиле, которое подошло хотя бы одному файлу. В него уходят только эти файлы, а не всё подряд.

Существующие типы в `internal/rules` становятся реестром плейсхолдеров: `map[string]func(*FileInfo) string`. Неиспользуемое поле `IsPrimary` удаляется. Разбор строк дат в `extractYear` и `extractMonth` исчезает вместе с форматом `January 2006`.

### 3.3 Пресеты и конфиг

Встроенные пресеты лежат в бинаре (`//go:embed presets.json`):

| Пресет | Правила |
|---|---|
| `downloads` (по умолчанию) | всё → `{category}` |
| `photos` | `images`, `videos` → `{year}/{month}`; остальное не трогается |
| `by-date` | всё → `{year}/{month}` |
| `by-type` | всё → `{category}/{ext}` |

Конфиг пользователя: `<os.UserConfigDir()>/fiona/config.json`.

```json
{
  "default_preset": "work",
  "action": "move",
  "on_conflict": "rename",
  "presets": {
    "work": {
      "description": "Счета по годам, фото по месяцам, остальное по типу",
      "rules": [
        { "match": { "name": "invoice*", "ext": ["pdf"] }, "to": "invoices/{year}" },
        { "match": { "category": ["images"] }, "to": "photos/{year}/{month}" },
        { "to": "{category}" }
      ]
    }
  }
}
```

- Формат — JSON: стандартная библиотека, тот же формат у `--ml-config`, и его надёжнее всего выдают LLM.
- Пользовательский пресет с именем встроенного заменяет его.
- Отсутствие конфига — не ошибка. Битый конфиг — ошибка с указанием места.
- `fiona presets` печатает список с описаниями; `fiona presets show NAME` — JSON пресета как заготовку.

### 3.4 Категории и даты

**Категории.** Расширение сравнивается в нижнем регистре.

| Категория | Расширения |
|---|---|
| `images` | jpg jpeg png gif bmp webp svg heic heif avif tif tiff ico psd cr2 cr3 nef arw dng raf orf rw2 |
| `videos` | mp4 mov avi mkv webm flv wmv m4v mpg mpeg 3gp mts |
| `audio` | mp3 wav flac aac ogg m4a opus wma aiff |
| `documents` | pdf doc docx odt rtf txt md pages xls xlsx ods csv numbers ppt pptx odp key epub fb2 mobi djvu |
| `archives` | zip rar 7z tar gz tgz bz2 xz zst |
| `installers` | dmg pkg exe msi deb rpm apk appimage iso |
| `code` | go py js ts jsx tsx java c h cpp hpp rs rb php sh html css json xml yaml yml toml sql ipynb |
| `other` | всё остальное |

Переименования: `audios` → `audio`, `applications` → `installers`, `unknown` → `other`. Критерий `mimetype` остаётся синонимом `category`.

**Определение по содержимому.** Если расширения нет или оно неизвестно, читаются первые 512 байт и вызывается `http.DetectContentType`. Соответствие: `image/*` → `images`, `video/*` → `videos`, `audio/*` → `audio`, `application/pdf` и `text/*` → `documents`, zip/gzip/rar/7z → `archives`. Чтение ленивое: только когда категория нужна правилу.

**Даты.** В `FileInfo` строка `Date` заменяется двумя полями:

```go
ModTime time.Time
Taken   *time.Time // дата съёмки из EXIF, если есть
```

Плейсхолдеры дат берут `Taken`, а при его отсутствии — `ModTime`.

EXIF читается лениво: только для категории `images` и только если в подошедшем правиле есть плейсхолдер даты. Нужен тег `DateTimeOriginal` из JPEG, TIFF и HEIC. В стандартной библиотеке Go разбора EXIF нет, нужна зависимость без cgo. Кандидат — `github.com/evanoberholster/imagemeta`; актуальность и поддержку HEIC проверить при реализации. Запасной вариант — собственный разбор сегмента APP1 только для JPEG.

### 3.5 Конвейер как библиотека

Оркестровка переезжает из `main.go` в пакет `internal/app`, чтобы CLI и TUI вызывали одно и то же.

```go
type Request struct {
    Source, Dest      string
    Rules             []config.Rule
    Action            string
    OnConflict        string
    Recursive, Hidden bool
    Workers           int
    MLConfigPath      string
}

func BuildPlan(ctx context.Context, req Request, rep sorter.Reporter) (*sorter.Plan, error) // сканирование, классификация, план
func Execute(ctx context.Context, plan *sorter.Plan, rep sorter.Reporter) (sorter.Summary, error)
func BuildUndo(journalPath string) (*sorter.UndoPlan, error)
func ExecuteUndo(ctx context.Context, plan *sorter.UndoPlan, rep sorter.Reporter) (sorter.Summary, error)
```

`BuildPlan` ничего не меняет на диске. `Execute` открывает журнал и запускает исполнитель.

### 3.6 TUI

TUI перестаёт возвращать `Result` в `main` и сам ведёт конвейер через `internal/app`.

Главная идея — **живой предпросмотр**: результат виден, пока пользователь выбирает папку и пресет. Отдельных экранов «настройка» и «предпросмотр» нет — это один экран, а подтверждение — модальный вопрос поверх него. Путь до результата: выбрать папку → `enter` → `y`.

Состояния:

```
main ─enter→ confirm ─y→ running → done ─n→ main
 │ h            └─esc→ main          │ u
 ↓                                   ↓
history ─enter→ undoConfirm ─y→ running → done
```

Главный экран:

```
 FIONA  ~/Downloads                                 move · into same folder
╭ Folder ──────────────────────╮╭ Result · preset downloads ───────────────╮
│ ▾ ~/                         ││  images/      86 files   412 MB          │
│   ▸ Desktop/                 ││  documents/   61 files    95 MB  exists  │
│   ▾ Downloads/   214 files   ││  archives/    12 files   1.2 GB          │
│     ▸ old/                   ││  installers/   9 files   2.1 GB          │
│   ▸ Documents/               ││  other/       38 files    52 MB          │
│   ▸ Movies/                  ││                                          │
│                              ││  Left as is: 1 folder                    │
╰──────────────────────────────╯╰──────────────────────────────────────────╯
 Preset  [downloads]  photos  by-date  by-type  custom
 enter move 214 files   p preset   c copy   d destination   h history   ? help
```

| Экран | Содержимое | Клавиши |
|---|---|---|
| `main` | слева дерево папок, справа план для выбранной папки и пресета; снизу пресеты и подсказки | `↑↓←→` — дерево; `tab` — фокус дерево ⇄ план (в плане `→` раскрывает папку до файлов); `p` / `shift+p` — пресет; `c` — move/copy; `d` — другая папка назначения; `r` — подпапки; `.` — скрытые; `enter` — выполнить; `h` — история; `?` — все клавиши; `q` — выход |
| `confirm` | вопрос из 3.8: `Move 214 files (1.8 GB) into 6 folders?` | `y` / `enter` — да, `n` / `esc` — назад |
| `running` | полоса прогресса (при `copy` — по байтам), текущий файл, счётчики | `ctrl+c` — мягкая остановка |
| `done` | итог одной строкой, проблемы — списком | `u` — откатить, `o` — открыть папку, `n` — новая сортировка, `q` — выход |
| `history` | запуски: когда, где, сколько, состояние | `enter` — откатить выбранный, `esc` — назад |
| `undoConfirm` | что и куда вернётся, с названием запуска и датой | `y` / `n` |

Детали:

- **Старт.** Дерево раскрыто до `SOURCE` или текущей папки, курсор на ней, план для неё строится сразу. Сейчас оба дерева стартуют в `~`.
- **Пересчёт.** Смена папки запускает новое сканирование через ~200 мс после последнего нажатия; предыдущее отменяется через `context`. Смена пресета, действия или папки назначения пересчитывает план в памяти, без сканирования. Пока идёт сканирование, в панели плана — спиннер со счётчиком файлов. Числа и рендер плана общие с CLI (3.8).
- **ML сам не запускается.** Если в пресете есть `{ml}`, панель показывает `ML classification: 86 images — press m`. Классификация идёт с прогрессом, результат кэшируется для папки.
- **Селектор пресета** заменяет пару «Primary / Secondary» с их жаргоном (`mimetype`). У каждого пресета видно описание. Значение `custom` раскрывает поле шаблона `--to` со списком плейсхолдеров; неизвестный плейсхолдер подсвечивается, план не строится.
- **Папка назначения** по умолчанию — та же. `d` открывает дерево назначения поверх панели плана, `esc` в нём возвращает «в ту же папку». Двух постоянных деревьев нет.
- **Клавиши вместо кнопок.** Кнопок Sort / Undo / Quit нет, нижняя строка — подсказки для текущего фокуса. Это убирает класс ошибок со случайным кликом: сейчас при фокусе на Sort клик в любое место запускает действие (`internal/tui/model.go:121-132`). Клик по подсказке срабатывает, только если `handleClick` вернул признак попадания в неё.
- **Логотип** показывается, только если под ним остаётся не меньше 20 строк для дерева и плана; иначе — строка заголовка.
- **`o` на экране `done`** открывает папку назначения: `open` на macOS, `xdg-open` на Linux, `explorer` на Windows.
- **До `y` на экране `confirm` диск не меняется.**
- **Фоновая работа** идёт в `tea.Cmd`. Прогресс приходит через канал, который читает повторяющаяся команда; реализация `sorter.Reporter` пишет в этот канал.
- **Мелочи:** `renderTooNarrow` падает при ширине меньше 2; ширина логотипа считается в байтах, а не через `lipgloss.Width`; `tab` во время ввода пути оставляет режим редактирования включённым.
- `docs/tui-api.md` описывает старый контракт и переписывается.

### 3.7 История и откат

Глобальный индекс запусков: `<os.UserConfigDir()>/fiona/history.jsonl`, права `0600`.

```jsonl
{"run_id":"20261010-153012-a1b2","started_at":"2026-10-10T15:30:12Z","source":"/Users/a/Downloads","dest":"/Users/a/Downloads","journal":"/Users/a/Downloads/.fiona/runs/20261010-153012-a1b2.jsonl","action":"move","planned":214}
```

- Строка дописывается в начале запуска, сразу после создания журнала. Если индекс недоступен — предупреждение, запуск продолжается.
- Состояние запуска (завершён, прерван, откатан) читается из самого журнала. Индекс его не дублирует.
- **`fiona undo`** без аргументов берёт последний неоткатанный запуск с доступным журналом. Повторный вызов откатывает предыдущий — как Ctrl+Z. Предпросмотр всегда называет запуск и дату.
- **`fiona undo RUN-ID`** принимает префикс идентификатора. `--log` и `--dest` из Этапа 0 остаются.
- **`fiona history`** печатает таблицу: идентификатор, дата, source → dest, число файлов, состояние. Недоступный журнал помечается.

### 3.8 Вывод и сообщения

Тексты — на английском (решение Этапа 0). Рендер переезжает из `sorter.Plan.Print` и `UndoPlan.Print` в `internal/cli/render.go`: `sorter` отдаёт данные (`Stats`, группы по папкам), CLI и TUI рисуют их одним кодом. Это продолжает правило Этапа 0 «`sorter` ничего не печатает».

**План** — только папки, без файлов:

```
Sorting ~/Downloads with preset "downloads"

  images/       86 files   412 MB
  documents/    61 files    95 MB   exists
  other/        38 files    52 MB   .torrent 20, .ics 9, .bin 4, …

  Renamed on conflict: 4
  Left as is: 3 folders, 2 files that match no rule

Move 185 files (559 MB) into 3 folders? [y/N/l]
```

- Первая строка называет источник правил: `with preset "work" (default from config)`, `with --to "{year}/{month}"`, `by year, then month` для `-c`/`-t`. Так видно, почему поведение изменилось после правки конфига.
- Вложенные шаблоны (`{year}/{month}`) показываются деревом до двух уровней. Если папок верхнего уровня больше 12 — первые 12 по числу файлов и `… and 9 more folders`.
- Колонки выровнены, размеры — по правому краю. Пути — с `~` вместо домашней папки, внутри плана — относительно dest.
- `exists` — папка уже есть, файлы сольются с её содержимым. Папка, отличающаяся только регистром (`Images/` при плане `images/`), считается той же: используется существующая, вторая не создаётся.
- Для `other/` — три самых частых расширения: подсказка, какое правило дописать.
- Счётчики с нулём не печатаются. Отклонённые операции и сбои сканера — с причинами, не больше 5 строк, дальше `… and N more (see --list)`.
- Пустой результат объясняет причину: `Nothing to sort in ~/x: 3 folders are left as is. Use -r to sort files inside them.`

**Полный список.** `-l`, `--list` печатает каждый файл: `a.jpg → images/a.jpg`, переименования помечены. Ответ `l` на вопрос печатает тот же список и задаёт вопрос снова. `-v` остаётся за `--version`.

**Вопрос** называет действие, объём и место: `Move 214 files (1.8 GB) into 6 folders?`, при другой папке — `Copy 214 files (1.8 GB) into 6 folders in ~/Sorted?`. Ответ по умолчанию — нет. Если stdin закрыт до ответа: `No answer: nothing is changed. Use --yes to run without confirmation.`

**Выполнение и итог.**

- Полоса прогресса — только в терминале и только если запуск длится дольше ~0.5 с; при `copy` — по байтам. После завершения строка стирается.
- Итог — одна строка, проблемы — под ней:

```
✓ Moved 214 files in 1.2s. Undo: fiona undo

! Moved 211 of 214 files, 3 failed:
  ✗ locked.pdf: permission denied
  …
  Undo: fiona undo

Stopped after 120 of 214 files. Undo: fiona undo
```

- Подсказка — `fiona undo` без аргументов (индекс из 3.7 находит запуск). `--dest` или `--log` добавляются, только если запуск не попал в индекс.
- Путь к журналу виден в `fiona history`, после запуска не печатается. Об очистке корзины сообщается только при ошибке.

**Откат:**

```
Undo the run from today 15:28 (moved 214 files in ~/Downloads)? [y/N] y
✓ Restored 214 files, removed 6 empty folders.
```

- Даты — `today 15:28`, `yesterday 09:10`, дальше `12 Oct 15:28`; то же в `fiona history`.
- «Нечего откатывать» — не ошибка, код 0: `Nothing to undo: the last run in ~/Downloads (today 15:28) is already undone. See fiona history.`

**Ошибки.**

- Формат: `fiona: <что случилось>` и, если есть, вторая строка с подсказкой. Без `Something went wrong` и `!!! ⚠ … ⚠ !!!`.
- Опечатка в подкоманде, пресете, критерии или плейсхолдере — с ближайшим вариантом (расстояние Левенштейна ≤ 2) и списком допустимых:

```
fiona: unknown preset "photso". Did you mean "photos"?
Available: downloads, photos, by-date, by-type, work

fiona: preset "work", rule 2: unknown placeholder {yaer}. Did you mean {year}?
```

- Коды выхода: `0` — успех, отмена, нечего делать; `1` — ошибка выполнения; `2` — ошибка в аргументах или конфиге, диск не тронут.

**Цвет.** В терминале — через `lipgloss` (уже в зависимостях): `✓` зелёный, `!` жёлтый, `✗` красный, второстепенное приглушено. Если stdout не терминал или задан `NO_COLOR` — без цвета и без полосы прогресса.

## 6. Ломающие изменения

- Действие по умолчанию — `move`, раньше `copy`.
- Dest по умолчанию равен source; раньше оба были текущей папкой независимо друг от друга.
- Имена папок: `audios` → `audio`, `applications` → `installers`, `unknown` → `other`.
- `date` даёт `2025-01-15`, `month` — `01`.
- Расширения в именах папок — в нижнем регистре.
- Длинные флаги с одним дефисом (`-criteria`) перестают работать.
- TUI: `tui.Run()` больше не возвращает `Result`.
- Вывод плана и итога другой: список файлов — только с `--list`, путь к журналу — в `fiona history`.
- Ошибки в аргументах и конфиге завершаются с кодом 2, раньше 1.
- Версия 0.5.0.

## 7. Решения по открытым вопросам

Приняты при реализации 2026-10-17 по предложениям этой спеки; любое можно пересмотреть.

1. **Имена папок.** Переименованы: `audio`, `installers`, `other`.
2. **Формат конфига.** JSON.
3. **`fiona` без аргументов.** В терминале — TUI, иначе краткая справка и код 2.
4. **Папки верхнего уровня.** Остаются на месте.
5. **Зависимости.** `spf13/pflag` и `golang.org/x/term` (уже был в косвенных). Библиотеки EXIF нет: `evanoberholster/imagemeta` v1.1.0 требует Go 1.27 и тянет полдюжины модулей, поэтому разбор свой (см. раздел 8). `charmbracelet/bubbles` больше не нужен и убран из `go.mod`.
6. **Регистр категорий.** `images/`; существующая папка в другом регистре переиспользуется.
7. **Логотип в TUI.** На главном экране, когда под ним остаётся не меньше 20 строк.
8. **Код выхода 2.** Введён.

## 8. Как реализовано

Отличия от текста выше и то, что в нём не было описано.

- **Рендер** — пакет `internal/report`, а не `internal/cli/render.go`: его импортируют и CLI, и TUI, а TUI не должен зависеть от `cli`.
- **Правила** — типы `Rule` и `Match` в `internal/rules` (не в `config`): `config` проверяет пресеты через `rules`, обратная зависимость дала бы цикл. Компилированный набор — `rules.Set`; планировщик принимает интерфейс `sorter.Router`. Критерий `ext` принимается как синоним `extension`.
- **Планировщик** — `NewPlan(scanned *scanner.Result, router, params)`. Файлы без правила попадают в `Plan.Unmatched` и в журнал не пишутся, формат журнала не менялся. Папки, которые сканер не открыл, — в `Result.Kept` → строка `Left as is`; папки, куда как раз идут файлы плана, туда не считаются.
- **Категория и дата** — `FileInfo.Category()` и `FileInfo.Taken()` ленивые, с `sync.Once`. Пустой файл без расширения — `other`, а не `documents`. Расширения `.torrent`, `.ics` и прочие текстовые попадают в `documents` по содержимому — так работает правило из 3.4.
- **EXIF** — `internal/scanner/exif.go`: JPEG (APP1), TIFF и RAW на нём (DNG, CR2, NEF, ARW, ORF, RW2), Fujifilm RAF (встроенный JPEG), HEIC/HEIF/AVIF (элемент `Exif` через `iinf`/`iloc`). CR3 не поддерживается. Берётся `DateTimeOriginal`, затем `DateTimeDigitized`. Генератор тестовых файлов — `internal/scanner/exiftest`.
- **История** — `internal/history`; состояния: `done`, `done with errors`, `interrupted`, `undone`, `journal missing`, `journal unreadable`. `fiona undo` без аргументов: сначала история, затем журналы текущей папки (запуски 0.4.0). Явно названный уже откатанный запуск (`RUN-ID`, `--log`) — ошибка с кодом 1; «нечего откатывать» без аргументов и с `--dest` — код 0.
- **Каталог конфига** переопределяется переменной `FIONA_CONFIG_DIR`; тесты используют её, чтобы не трогать настоящую историю.
- **Сканер** принимает `Options.Context`: TUI отменяет устаревшее сканирование.
- **TUI.** В панели плана `l` показывает список всех файлов (как в CLI) вместо раскрытия папки по `→`. Прогресс выполнения читается по таймеру раз в 100 мс из счётчиков под мьютексом, а не через канал: так рабочие потоки никогда не ждут экран. `h` — история, поэтому vim-клавиша `h` в дереве не работает (стрелки работают). Нажатия, пришедшие одним сообщением (`"pp"`), разбираются по одному. Поле шаблона и поле пути — свои простые поля ввода: `bubbles/textinput` тянул `atotto/clipboard`.
- **Не сделано:** CHANGELOG (файл удалён, решено не трогать — см. Этап 0); скриншот `assets/screenshot_tui.png` в README показывает старый TUI.
