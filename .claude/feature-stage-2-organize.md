# Этап 2 — Организация через локальную LLM

| | |
|---|---|
| Статус | черновик, не реализован |
| Дата | 2026-11-03 |
| Зависит от | `feature-stage-1-simplicity.md`: правила `rules.Rule`, конвейер `app`, сводка `report`, предпросмотр в TUI |
| Следом | содержимое файлов (текст, картинки), эмбеддинги и кластеры, встроенная модель вместо `fiona-classifier` |

## 1. Зачем

Пресеты Этапа 1 раскладывают файлы по типу и дате, но не понимают, *зачем* файл нужен. `Rechnung_Telekom_2024-03.pdf`, `договор аренды.docx` и `Lebenslauf_2025.pdf` попадают в одну `documents/`, хотя человек разложил бы их в «Финансы», «Жильё» и «Работа». Правилами такое не описать: маски имён не знают, что `Rechnung` и `счёт` — одно и то же.

Нужен сценарий «вот папка — организуй красиво». Локальная LLM понимает имена файлов на русском, немецком и английском и может предложить структуру. FIONA превращает её ответ в обычный план, поэтому предпросмотр, подтверждение, журнал и undo работают как для пресетов.

Этот этап — общий вариант: модель видит только имена и метаданные, содержимое файлов не читается.

### Целевой сценарий

$ fiona organize ~/Downloads

`r` — попросить другой вариант. `--hint "работу по годам, фото не трогать"` — пожелание своими словами.

## 2. Цели

- **Ц1.** `fiona organize <папка>` раскладывает файлы по смыслу без единого правила.
- **Ц2.** Имена на русском, немецком и английском понимаются; папки называются на выбранном языке.
- **Ц3.** Модель только предлагает. Диск меняет FIONA — по тому же плану, с подтверждением и undo.
- **Ц4.** Только локально: Ollama на этой машине. Модели уходят имена, размеры и даты, содержимое — никогда.
- **Ц5.** Плохой ответ модели не портит данные: негодные папки отбрасываются, неразложенные файлы остаются на месте.
- **Ц6.** Повторный запуск кладёт новые файлы в уже созданные папки, а не придумывает структуру заново.
- **Ц7.** Ожидание видно: прогресс по шагам, Ctrl-C прерывает в любой момент без изменений на диске.

### Вне рамок

- Чтение содержимого: текст, PDF, картинки.
- Эмбеддинги, кластеризация, kNN.
- Встроенная модель без Ollama и замена `fiona-classifier`; `{ml}` работает как раньше.
- Переименование файлов.
- Перемещение папок целиком: папки верхнего уровня остаются на месте, как в Этапе 1.
- Диалог с моделью («объедини эти две папки»): есть только `r` и `--hint`.
- Сохранение результата как пресета: формат позволяет (3.5), команды нет.
- Облачные LLM.

## 3. Решения

### 3.1 Конвейер

```
scan → элементы → профиль → LLM: структура → LLM: раскладка (батчами) → проверка → []rules.Rule → план → …как в sort
```

1. **Скан** — как в `sort`: те же `-r`, `--hidden`, проекты и бандлы не вскрываются.
2. **Элементы** (3.3): файлы с одним шаблоном имени склеиваются в серию — 340 `IMG_####.JPG` модель видит одной строкой.
3. **Профиль**: элементы плюс папки, уже лежащие в dest.
4. **Структура** — один запрос: модель предлагает список папок (3.4).
5. **Раскладка** — запросы батчами: для каждого элемента модель выбирает папку из этого списка.
6. **Проверка** (3.6): всё, что не прошло, остаётся на месте.
7. **Правила** (3.5): ответ превращается в `[]rules.Rule`; дальше работает код Этапа 1 без изменений.

Шагов два, а не один, потому что мелкие модели, называя папку для каждого файла отдельно, плодят почти одинаковые (`Finance`, `Finances`, `Rechnungen`). Когда список папок готов заранее, выбор на шаге 5 ограничен JSON-схемой с `enum`, и новую папку модель придумать не может.

### 3.2 Командная строка

```
fiona organize [flags] [SOURCE] [DEST]
```

Флаги — как у `sort`, кроме источников правил (`-p`, `--to`, `-c`, `-t`, `--ml-config`). Новые:

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `--hint <text>` | — | пожелание к структуре, на любом языке |
| `--lang ru\|de\|en` | `organize.lang` → локаль (`LC_ALL`, `LANG`) → `en` | язык имён папок |
| `--model <name>` | `organize.model` | модель Ollama |

Вопрос подтверждения принимает `r`: шаги 4–5 повторяются со следующим `seed`, печатается новый план, вопрос задаётся снова. `--dry-run` печатает план и выходит, `--yes` выполняет без вопроса.

Конфиг:

```json
{
  "organize": {
    "model": "qwen2.5:7b",
    "lang": "ru",
    "ollama_url": "http://localhost:11434"
  }
}
```

Адрес Ollama: `organize.ollama_url` → `OLLAMA_HOST` (так его читает и сама Ollama) → `http://localhost:11434`. Если адрес не на этой машине, заголовок плана добавляет строку `File names are sent to http://192.168.1.5:11434`.

Пока модель по умолчанию не выбрана (раздел 7, вопрос 2), без `--model` и `organize.model` команда перечисляет установленные модели и просит выбрать.

Вывод CLI — по-английски (решение Этапа 0); на выбранном языке только имена папок и их описания.

### 3.3 Элементы и профиль

**Элемент** — то, о чём спрашивают модель: один файл или серия.

**Серия** — не меньше 3 файлов с одним расширением и одним шаблоном имени. Шаблон: имя без расширения в нижнем регистре, каждая последовательность цифр → `#`, хвосты копий (` (1)`, ` copy`, ` Kopie`, ` копия`) убраны. В шаблоне должна остаться хотя бы одна буква: `1.pdf`, `2.pdf` — не серия, такие имена ничего не говорят о связи файлов.

| Файлы | Шаблон |
|---|---|
| `IMG_0001.JPG` … `IMG_0340.JPG` | `img_#.jpg` |
| `Screenshot 2025-01-03 at 12.00.01.png`, … | `screenshot #-#-# at #.#.#.png` |
| `Снимок экрана 2025-01-03 в 12.00.01.png`, … | `снимок экрана #-#-# в #.#.#.png` |
| `Rechnung_2024_03.pdf`, `Rechnung_2024_04 (1).pdf`, … | `rechnung_#_#.pdf` |

Вся серия получает одну папку.

Строки элементов в запросе:

```
17 | Rechnung_Telekom_2024-03.pdf | documents | 120 KB | 2024-03
18 | IMG_####.JPG ×340 | images | 1.2 GB | 2019-05…2024-11
19 | Work/2023/Q3 report.xlsx | documents | 48 KB | 2023-10
```

- Имя серии — имя первого файла с цифрами, заменёнными на `#`.
- С `-r` вместо имени — путь относительно source: родительские папки тоже подсказка.
- Дата — `FileInfo.Date()` (дата съёмки для фото) с точностью до месяца.

**Существующие папки.** Каждая папка верхнего уровня в dest: имя, число файлов, до 5 имён внутри (`os.ReadDir`, без рекурсии). Модель просят класть файлы в подходящие из них — отсюда Ц6. Проекты и бандлы (`Result.Kept`) показываются с пометкой `project`, класть в них нельзя.

### 3.4 Запросы к модели

Ollama, `POST /api/chat`, `stream: false`.

| Параметр | Значение | Зачем |
|---|---|---|
| `format` | JSON-схема ответа | ответ всегда разбирается; папки на шаге 5 — только из `enum` |
| `options.temperature` | `0` | одинаковый вход — одинаковый ответ |
| `options.seed` | `1`; после `r` — следующий | `r` даёт другой вариант |
| `options.num_ctx` | по размеру запроса, не больше контекста модели | контекст Ollama по умолчанию мал, а лишнее она обрезает молча |
| `think` | `false`, если модель умеет рассуждать | рассуждения долгие и здесь не нужны |
| `keep_alive` | `5m` | модель не выгружается между батчами |

Перед первым запросом: `GET /api/tags` — модель установлена; `POST /api/show` — длина контекста и умеет ли модель рассуждать.

Инструкции — на английском (мелкие модели лучше всего следуют им), язык имён папок указан явно. Тексты промптов — `internal/organize/prompts/*.txt` (`go:embed`): их правят и сравнивают, не трогая код.

**Шаг «структура».** Вход: элементы (если их больше 300 — сводка по категориям и расширениям, все серии и 200 случайных одиночных файлов), существующие папки, `--hint`. Выход:

```json
{ "folders": [
  { "path": "Финансы", "about": "счета, выписки, налоги" },
  { "path": "Фото/{year}", "about": "фотографии по году съёмки" }
] }
```

Что сказано в промпте:

- 3–12 папок, вложенность не больше 2;
- группировать по назначению (финансы, работа, учёба, поездки), а по типу — только когда имена ничего не говорят (`IMG_####`, скриншоты, установщики);
- подходящие существующие папки переиспользовать под их именами;
- одна папка для остального (раздел 7, вопрос 5);
- в `path` можно `{year}` и `{month}` — так фото и сканы раскладываются по датам без отдельных правил.

**Шаг «раскладка».** Батчи по ≤ 80 элементов, по очереди: Ollama по умолчанию всё равно обрабатывает запросы к модели последовательно. Вход: папки с описаниями и элементы батча. Выход:

```json
{ "files": [ { "id": 17, "folder": "Финансы" }, { "id": 18, "folder": "Фото/{year}" } ] }
```

`folder` в схеме — `enum` из путей шага «структура».

**Переполнение контекста.** Размер запроса оценивается сверху: байты UTF-8 / 2 токена. Если в ответе `prompt_eval_count` у самой границы `num_ctx`, запрос считается обрезанным: батч делится пополам и повторяется.

### 3.5 Ответ → правила

Ответ становится обычным `[]rules.Rule`:

- одиночный файл → `{"match": {"name": "<имя, спецсимволы glob экранированы>"}, "to": "<папка>"}`;
- серия → `{"match": {"name": "img_*.jpg"}, "to": "<папка>"}`: `#` в шаблоне → `*`;
- сначала все точные имена, потом серии — серия не перехватывает файл, разложенный отдельно.

Что это даёт: `{year}` рендерит готовый `Template`, каждый компонент проверяет санитайзер Этапа 0, а планировщик, сводка, журнал и TUI не меняются. Результат при желании сохраняется как пресет — это обычный JSON правил.

Ограничение: с `-r` одинаковые имена в разных подпапках получают папку первого из них. Случай редкий, ради него `Match` не расширяется.

### 3.6 Проверка ответа

| Проблема | Что делаем |
|---|---|
| ответ не разбирается или не подходит под схему | тот же запрос ещё раз, затем ошибка шага; диск не тронут |
| папка: абсолютный путь, `..`, вложенность больше 2, неизвестный плейсхолдер, пустое имя после санитайзера | папка отбрасывается |
| папка внутри проекта или бандла | отбрасывается |
| две папки, совпадающие без учёта регистра | склеиваются |
| больше 12 папок | берутся первые 12 |
| годных папок не осталось | ошибка `the model proposed no usable folders`, код 1 |
| элемент без папки, папка не из списка | пропущенные элементы — ещё одним запросом; что осталось, остаётся на месте |
| неизвестный `id` | игнорируется |
| повтор `id` | берётся первый ответ |
| в папку не попал ни один файл | в плане её просто нет |

Неразложенные файлы попадают в `Plan.Unmatched`; в сводке — строка `Not placed by the model: 4 files`.

### 3.7 Пакеты

```
internal/ollama/      — клиент: Tags, Show, Chat с format; отмена через context
internal/organize/    — items.go (серии), profile.go, prompts/, schema.go, validate.go, rules.go
internal/app/         — Organize: элементы → запросы → проверка → правила
cmd/fiona/organize.go
```

`organize` зависит от интерфейса, а не от Ollama:

```go
type Model interface {
    Name() string
    // Generate returns JSON that matches the schema.
    Generate(ctx context.Context, req Request) ([]byte, error)
}

type Request struct {
    System, User string
    Schema       json.RawMessage
    Seed         int
}
```

Так позже подключается встроенная модель, а тесты используют фальшивую.

`app.Organize` возвращает правила и описания папок. Правила проходят `rules.Compile` и уходят в `Request.Rules` как обычно; описания — в `report.PlanView`, для колонки сводки.

### 3.8 TUI

- В списке пресетов появляется `organize` — после пользовательских, перед `custom`.
- Выбор не запускает модель. Панель плана пишет `Press m to ask qwen2.5:7b`; `m` — та же клавиша, что запускает классификатор для `{ml}`, то есть «спросить модель».
- Повторное `m` при готовом результате — другой вариант (следующий `seed`).
- Прогресс — в строке подсказок, `esc` отменяет запрос.
- Результат живёт, пока не сменились папка, `-r` или `--hidden`. Смена копирования, конфликтов или dest модель не перезапускает.
- Поле шаблона (`t`) у `organize` становится полем пожелания (`--hint`).

## 4. План реализации

1. `internal/ollama`: клиент, тесты на `httptest`.
2. `internal/organize`: серии и профиль, промпты, схемы, проверка, правила; тесты с фальшивой `Model`.
3. `app.Organize`, `cmd/fiona/organize.go`, ответ `r` в `cli.Prompt`, колонка описаний в `report`.
4. TUI.
5. README и справка.
6. Оценка на реальных моделях. Наборы `testdata/organize/*.txt` — списки имён: смешанная Downloads на русском, немецком и английском (~150 имён), только фото, только документы, папка с уже разложенными подпапками. Тест с тегом `ollama` создаёт пустые файлы с этими именами, прогоняет 3–4 модели и печатает структуру, время и долю разложенных файлов. По нему выбираются модель по умолчанию, размер батча и формат ответа; итоги — в раздел 8.

## 6. Ломающие изменения

Нет. `sort`, пресеты, `{ml}` и `fiona-classifier` не меняются. В конфиге появляется необязательный раздел `organize`.

## 7. Открытые вопросы

1. **Команда.** Предложение: отдельная `fiona organize`, а не `fiona sort --ai`: у неё свой источник правил и свои флаги, а флаги правил `sort` ей не нужны.
2. **Модель по умолчанию.** Предложение: выбрать по оценке (шаг 6) из `qwen2.5:7b`, `qwen3:8b`, `gemma3:4b`, `gemma3:12b` — у всех приличные русский и немецкий. От объёма памяти зависит, потянет ли машина 12B.
