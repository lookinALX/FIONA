## 1. Зачем

В обычных сценариях FIONA молча уничтожает файлы и сообщает об успехе. Пока это не исправлено, на исполнитель нельзя опираться ни в TUI, ни в будущих LLM-планах.

Все проблемы ниже, кроме помеченных «по коду», воспроизведены на тестовых данных. Номера строк — на момент написания.

| ID | Проблема | Причина |
|---|---|---|
| B1 | Повторный `move`, когда dest внутри source или равен ему, удаляет все файлы | `ProcessFile` делает `os.Remove(destination)`, когда source и destination — один файл (`internal/sorter/executer.go:155`) |
| B2 | Одноимённые файлы из разных подпапок затирают друг друга, отчёт «Succeeded: 2» | рекурсивный `Scan` + плоская папка назначения + `replace` по умолчанию |
| B3 | При `rename`/`skip` файлы теряются: из 200 одноимённых уцелело 123 и 196 | конфликт решается в воркерах без синхронизации; `generateNewName` создаёт и тут же удаляет заглушку (`executer.go:189-193`) |
| B4 | Undo после `skip`/`rename` удаляет или перезаписывает файлы, которые FIONA не создавала | журнал хранит папку, а не конечный путь; пропуск записан как `succeeded` (`internal/sorter/planner.go:52`) |
| B5 | Рекурсия разбирает на части `.git`, `.app`, проекты; сортируются скрытые файлы | `Scan` обходит всё дерево без исключений |
| B6 | `--dry-run=true --force yes` выполняет операцию | флаг управляет только печатью плана (`executer.go:51-63`) |
| B7 | Если dest не существует, остальные флаги не проверяются; dest создаётся даже при отказе | `ParseSortFlags` принимает первую ошибку `ErrDestNotExists` за успех (`internal/cli/options.go:132`) |
| B8 | `-w 0` ничего не делает и затирает прошлый журнал пустым | `validateWorkersFlag` отсекает только отрицательные |
| B9 | Журнал пишется один раз в конце и затирает предыдущий; после сбоя откат невозможен | `Journal.SaveAsJson` в конце `Executor.start` |
| B10 | Битый симлинк, симлинк на папку или недоступная подпапка обрывают весь запуск | `NewFileInfo` вызывает `os.Stat`; `Scan` возвращает первую же ошибку |
| B11 | Процесс `fiona-classifier` остаётся висеть после ML-запуска (по коду) | `defer server.Stop()` перед `os.Exit` в `cmd/fiona/main.go` |
| B12 | Мелочи (по коду): инвертированная проверка ошибки (`executer.go:156`); `y` + `\r\n` на Windows не распознаётся; undo создаёт не ту папку (`reverter.go:58`); код возврата всегда 0 | — |
| V1 | `fiona undo` полностью доверяет журналу и не спрашивает подтверждения: подложенный `fiona_logs.json` удалил файл в посторонней папке | `NewUndoPlan` исполняет пути из JSON как есть |
| V2 | Имя папки от правила может вывести запись за пределы dest (`../`) (по коду) | ключи `--ml-config` идут в `filepath.Join` без проверки (`internal/types/action.go:23`) |
| V3 | Симлинки разыменовываются: содержимое файла вне source копируется в dest; `os.Create` в dest идёт по ссылке | `os.Stat` в сканере, `os.Create` в `copyWithMetadata` |

## 2. Цели

Этап вводит шесть инвариантов. Каждое решение ниже существует ради одного из них.

- **И1. Ничего чужого не удаляем.** FIONA не удаляет и не перезаписывает файл, который не создала сама. Вытесняемый при `replace` файл уезжает в корзину.
- **И2. Файл не пропадает.** После запуска каждый исходный файл находится либо на прежнем месте, либо по конечному пути из журнала.
- **И3. Пишем только в dest.** Ни имя папки от правила, ни симлинк не выводят запись наружу.
- **И4. Любой запуск откатывается.** В том числе прерванный. Undo возвращает ровно то, что сделал запуск.
- **И5. Dry-run ничего не меняет.** Ни файлов, ни папок, ни журнала.
- **И6. Отчёт совпадает с диском.** Счётчики и код возврата отражают реальный результат.

### Вне рамок

- Защита от сторонних процессов, которые меняют dest во время работы. Гарантируем только «не перезаписывать».
- ML: таймаут 60 с на один запрос, диагностика падения классификатора, возможная ошибка pickle в `DataLoader`. Нужен отдельный документ.
- TUI, пресеты, определение типов, формат дат, история запусков — Этап 1.
- Контрольные суммы при сверке файлов: сверяем размер и mtime.
- Повторный откат отката.

## 3. Решения

### 3.1 Сканер

Новая сигнатура: `Scan(root string, opt Options) (*Result, error)`.

```go
type Options struct {
    Recursive     bool     // по умолчанию false
    IncludeHidden bool     // по умолчанию false
    Exclude       []string // абсолютные пути: dest, если он внутри source
}

type Result struct {
    Files   []*FileInfo
    Skipped []SkippedEntry // {Path, Reason}
}
```

Правила обхода:

- **Без рекурсии по умолчанию.** Берутся только обычные файлы верхнего уровня; подпапки не трогаются. Рекурсия включается флагом `-r`.
- **Скрытое пропускается.** Всё, что начинается с точки, не сканируется без `--hidden`. Папка `.fiona` исключается всегда.
- **Симлинки не разыменовываются.** Тип берётся из `fs.DirEntry.Type()`, метаданные — из `d.Info()`. Симлинки и не-обычные файлы (сокеты, устройства, FIFO) попадают в `Skipped`.
- **Непрозрачные папки при `-r`.** Обход не заходит в папку, если её имя оканчивается на `.app`, `.bundle`, `.framework`, `.photoslibrary`, `.xcodeproj` или если она содержит `.git`, `.hg`, `.svn`.
- **Ошибки не фатальны.** Недоступный файл или подпапка попадают в `Skipped`, обход продолжается (`fs.SkipDir`). Фатальна только ошибка чтения корня.
- **Dest исключается.** Если dest лежит строго внутри source, его поддерево не сканируется. Корни сравниваются после `filepath.Abs` и `filepath.EvalSymlinks`.

`Skipped` печатается в плане отдельной строкой: «Пропущено: 3 (2 симлинка, 1 нет доступа)».

### 3.2 Имена папок и границы dest

Санитайзер применяется в планировщике к каждому компоненту пути, который вернуло правило. Правила его не вызывают.

`rules.SanitizeComponent(s string) string`:

1. Заменяет на `_`: `/`, `\`, NUL, управляющие символы и `< > : " | ? *`.
2. Убирает пробелы по краям и точки с пробелами в конце.
3. Пустую строку, `.` и `..` превращает в `_other`.
4. Зарезервированным именам Windows (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`) добавляет префикс `_`.
5. Обрезает до 120 байт по границе руны.

После сборки пути — две проверки: `filepath.IsLocal(relDir)` и `filepath.Rel(dest, target)` без `..`. Если любая не прошла, операция отклоняется на этапе плана.

**`os.Root` на этом этапе не используем.** `Root.Rename` требует, чтобы оба пути лежали в одном корне, а при перемещении source и dest — разные деревья. К тому же `Rename` и `MkdirAll` у `Root` появились только в Go 1.25, а в `go.mod` стоит 1.24.2. Санитайзер, `IsLocal`, `Lstat` и `O_EXCL` закрывают V2 и V3 без него.

### 3.3 Планировщик

Все конфликты решаются здесь, в одном потоке. В плане у каждой операции уникальный конечный путь, поэтому воркерам не о чем гоняться.

```go
// internal/types/action.go — простые данные, без импорта rules и scanner
type OpKind string

const (
    OpMove   OpKind = "move"
    OpCopy   OpKind = "copy"
    OpSkip   OpKind = "skip"   // конфликт при стратегии skip, диск не меняется
    OpNoop   OpKind = "noop"   // файл уже на своём месте
    OpReject OpKind = "reject" // небезопасный или невозможный путь
)

type Action struct {
    Seq        int
    Kind       OpKind
    SourcePath string    // абсолютный
    DestDir    string    // относительно dest, для дерева плана
    TargetPath string    // абсолютный конечный путь файла
    Size       int64
    ModTime    time.Time
    Conflict   string    // "", "renamed", "replaced"
    TrashPath  string    // куда уедет вытесняемый файл при replace
    Note       string    // причина для skip и reject
}
```

Поле `DestPath` (сейчас это папка) удаляется, чтобы старый смысл не перепутали с новым.

Алгоритм для каждого файла, файлы отсортированы по `SourcePath`:

1. Собрать `relDir` из компонентов правил через санитайзер и проверить границы (3.2). Не прошло — `OpReject`.
2. Если `dest/relDir` существует и это не папка — `OpReject`.
3. Кандидат: `target = dest/relDir/basename`.
4. Если source и target — один файл (равные пути или `os.SameFile`) — `OpNoop`.
5. Путь занят, если он зарезервирован более ранней операцией этого плана или существует на диске (`os.Lstat`, чтобы висячий симлинк тоже считался). Ключ резервирования — путь в нижнем регистре: имена, отличающиеся только регистром, считаются конфликтом на любой ФС.
6. Если занят, применить стратегию:
   - **`rename`** (новое значение по умолчанию): первое свободное `name_1.ext`, `name_2.ext`, … с проверкой и резерва, и диска.
   - **`skip`**: `OpSkip`.
   - **`replace`**: только если занявший — файл, существовавший до запуска. Он уедет в `TrashPath = dest/.fiona/trash/<run-id>/<relDir>/<name>`. Если путь занят другой операцией этого же плана или папкой — действует `rename`.
7. Зарезервировать `target`.

Заодно планировщик собирает список папок, которых ещё нет на диске. Он уходит в журнал и нужен для чистки при откате.

`Plan.Print` дополняется итогами: переименовано, заменено, пропущено, уже на месте, отклонено, пропущено сканером.

### 3.4 Исполнитель

Исполнитель больше не принимает решений: он выполняет готовые операции.

- **Сторож перед каждой операцией.** `Lstat(target)`: если путь занят, а операция не `replace`, она завершается ошибкой «назначение появилось после планирования». Исходник остаётся на месте.
- **`replace`.** Существующий файл сначала переименовывается в `TrashPath`. Корзина лежит внутри dest, поэтому это атомарный `rename` на той же ФС.
- **Перемещение.** `os.Rename`. При `EXDEV` — атомарная копия, затем удаление исходника.
- **Атомарная копия.** Запись во временный файл `.fiona-<run-id>-<seq>.part` в целевой папке, открытый с `O_CREATE|O_EXCL`. Затем `Sync`, `Close` с проверкой ошибки, `Chmod`, `Chtimes`, сторож и `Rename` на конечное имя. При любой ошибке временный файл удаляется.
- **Отмена.** `signal.NotifyContext` на SIGINT и SIGTERM. Воркеры доделывают текущий файл и останавливаются; журнал остаётся согласованным.
- **Без прямого вывода.** `sorter` не вызывает `fmt.Println` и `progressbar`. Прогресс идёт через интерфейс:

```go
type Reporter interface {
    Start(total int)
    Done(a types.Action, err error)
    Finish(s Summary)
}
```

Реализация для CLI оборачивает `progressbar`. На Этапе 1 TUI подставит свою.

`Summary` считает раздельно: перемещено/скопировано, переименовано, заменено, пропущено, уже на месте, отклонено, ошибок. Код возврата — 1, если есть ошибки или запуск прерван.

### 3.5 Журнал v2

Журнал становится записью с упреждением: сначала весь план, потом результаты по мере выполнения.

- **Формат:** JSON Lines, один файл на запуск.
- **Путь:** `<dest>/.fiona/runs/<run-id>.jsonl`. Флаг `--log <dir>` меняет папку.
- **Run ID:** `20261010-153012-a1b2` — время UTC и 4 случайных hex-символа.
- **Запись:** заголовок, все `mkdir` и `op` пишутся до первой операции и сбрасываются через `fsync`. Строки `done` дописываются под мьютексом без `fsync`. `fsync` — ещё раз в конце.
- **Нет журнала — нет запуска.** Если файл журнала не удалось создать, ни один файл не трогается.

```jsonl
{"type":"header","version":2,"run_id":"20261010-153012-a1b2","started_at":"2026-10-10T15:30:12Z","source":"/Users/a/Downloads","dest":"/Users/a/Downloads","file_action":"move","on_conflict":"rename","fiona_version":"0.4.0"}
{"type":"mkdir","path":"/Users/a/Downloads/images"}
{"type":"op","seq":0,"kind":"move","src":"/Users/a/Downloads/a.jpg","dst":"/Users/a/Downloads/images/a.jpg","size":2048,"mtime":"2026-09-01T10:00:00Z"}
{"type":"op","seq":1,"kind":"move","src":"/Users/a/Downloads/b.jpg","dst":"/Users/a/Downloads/images/b_1.jpg","size":512,"mtime":"2026-09-02T10:00:00Z","conflict":"renamed"}
{"type":"op","seq":2,"kind":"skip","src":"/Users/a/Downloads/c.pdf","dst":"/Users/a/Downloads/documents/c.pdf","note":"already exists"}
{"type":"done","seq":0,"status":"ok","size":2048,"mtime":"2026-09-01T10:00:00Z"}
{"type":"done","seq":1,"status":"failed","error":"permission denied"}
{"type":"footer","finished_at":"2026-10-10T15:30:14Z","ok":1,"failed":1,"skipped":1}
```

Поля `size` и `mtime` в `done` — фактические значения конечного файла после операции (`Lstat`). Отсутствие `footer` означает прерванный запуск. Читатель игнорирует последнюю строку, если она оборвана.

API пакета `journal`: `Writer.Begin(header, mkdirs, actions)`, `Writer.Done(seq, status, err, size, mtime)`, `Writer.Close(summary)`, `Read(path) (*Run, error)`.

### 3.6 Undo

Откат сам проходит через план, предпросмотр и подтверждение.

**Выбор журнала:** `--log <file>` — явно; `--dest <dir>` — последний неоткатанный запуск из `<dir>/.fiona/runs`; без флагов — то же для текущей папки.

**Проверка журнала (V1):**

- `source` и `dest` в заголовке — абсолютные пути.
- Каждый `dst` и `trash` лежит внутри `dest` из заголовка, каждый `src` — внутри `source`.
- При поиске через `--dest` заголовочный `dest` обязан совпасть с этой папкой.
- Журнал с неизвестной версией или нарушением любого пункта отклоняется целиком.

**Обработка операций в обратном порядке `seq`:**

| Запись | Действие |
|---|---|
| `skip`, `noop`, `reject` | ничего |
| `done: failed` | ничего |
| `move`, `done: ok` | сверить `dst` с записанными размером и mtime; убедиться, что `src` свободен; создать папку `src`; переместить обратно |
| `copy`, `done: ok` | сверить `dst`; удалить его |
| нет `done` (запуск прерван) | `move`: если `dst` есть, а `src` нет, и размер совпал — вернуть. `copy`: если `dst` есть и размер совпал — удалить |
| есть `trash` | после отката операции вернуть файл из корзины на место `dst`, если оно свободно |

Сверка: размер равен, mtime отличается не больше чем на 2 секунды. Файл, который не прошёл сверку, или занятое исходное место — пропуск с сообщением, без перезаписи.

**После операций:**

- Удалить оставшиеся `.fiona-<run-id>-*.part`.
- Удалить папки из записей `mkdir`, если они пусты, от глубоких к верхним. Сам dest и всё, что выше, не трогается.
- Дописать в журнал `{"type":"undone","at":"…"}`. Повторный откат такого журнала отклоняется.

Откат идемпотентен: если он прерван, повторный запуск пропустит уже возвращённые файлы.

**Предпросмотр перед подтверждением:**

```
Откат запуска 20261010-153012-a1b2 (move, 10.10.2026 15:30)
  вернуть в /Users/a/Downloads:   120 файлов
  восстановить из корзины:        3
  удалить пустых папок:           5
  пропустить (изменены позже):    2
Продолжить? [y/N]
```

**Журналы старого формата** (`fiona_logs.json`) отклоняются с пояснением: в них нет конечных путей, безопасный откат по ним невозможен.

### 3.7 Командная строка

`sort`:

| Флаг | Сейчас | Станет |
|---|---|---|
| `-n`, `--dry-run` | по умолчанию `true`; только печатает план | по умолчанию `false`; печатает план и выходит, диск не трогает; сильнее `--yes` |
| `-y`, `--yes` | нет | выполнить без вопроса |
| `--force yes` | пропуск подтверждения | устаревший синоним `--yes` с предупреждением; удалить через один релиз |
| `--on-conflict` | по умолчанию `replace` | по умолчанию `rename`; `replace` переносит старый файл в корзину |
| `-r`, `--recursive` | рекурсия всегда | по умолчанию выключена |
| `--hidden` | скрытые всегда включены | по умолчанию выключены |
| `-w`, `--workers` | 0 проходит | только ≥ 1; больше максимума — усечение с предупреждением, как сейчас |
| `--log` | папка для `fiona_logs.json`, по умолчанию текущая | папка журналов, по умолчанию `<dest>/.fiona/runs` |

`undo`: `--log <file>`, `--dest <dir>`, `-n`, `-y`, `-w`.

Поведение без `-n` и `-y` не меняется: план, вопрос, выполнение.

Правила разбора:

- Проверяются все флаги, ошибки собираются через `errors.Join` и печатаются вместе.
- Проверка идёт до любых побочных эффектов. Dest создаётся только перед выполнением.
- Ответ на вопрос: `strings.TrimSpace`, без учёта регистра, принимаются `y` и `yes`. Конец ввода означает «нет».

### 3.8 `main.go`

- `func main() { os.Exit(run(os.Args[1:])) }` — отложенные вызовы срабатывают, классификатор останавливается (B11).
- Флаги каждой подкоманды — в собственном `flag.NewFlagSet`, без правки `os.Args` и глобального набора.

## 6. Ломающие изменения

- Сканирование не рекурсивное и без скрытых файлов; прежнее поведение — `-r --hidden`.
- `--on-conflict` по умолчанию `rename`.
- `--dry-run` больше не выполняет операцию ни при каких флагах.
- Журнал: вместо `fiona_logs.json` в текущей папке — `<dest>/.fiona/runs/<run-id>.jsonl`. Старые журналы для отката не принимаются.
- `--force yes` устарел.
- Код возврата 1 при ошибках операций.
- Версия 0.4.0.

## 7. Решения по открытым вопросам

Приняты 2026-10-10.

1. **Корзина.** Автоочистка запусков старше 5 дней при выполнении `sort`.
2. **Старые журналы.** `fiona_logs.json` отклоняется с пояснением.
3. **Непрозрачные папки.** Список из 3.1 плюс `node_modules`, `go.mod`, `package.json`.
4. **`--force yes`.** Убран сразу, без переходного релиза.
5. **Опасные корни.** Отказов нет.

Пункт про CHANGELOG из шага 7 пропущен: файл удалён, решено не трогать.
